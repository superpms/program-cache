# 实现注意事项

## 这是文件缓存

当前实现没有使用 Redis、数据库或共享内存。所有数据都落在 `init()` 指定目录下的普通文件中。

适合：

- 轻量配置或权限缓存
- 单机运行环境
- 对缓存一致性要求不高的短期数据

不适合：

- 多节点共享缓存
- 需要原子自增、自减、队列、集合等 Redis 语义的场景
- 大量高频写入且需要精细淘汰策略的场景

## 空值语义

多个方法把 `empty()` 当作不存在判断：

- `exists()`
- `setnx()`
- `setnxCache()`

这会影响 `0`、`false`、空字符串、空数组等值。开发时如果需要缓存这些值，建议封装成非空结构，例如：

```php
Cache::set('flag', ['value' => false], 60);
```

## 过期语义

过期时间只在读取时判断。

- `expire <= 0`: 永不过期
- `expire > 0`: 保存为绝对时间戳
- 过期后 `get()` 返回默认值
- 过期文件不会自动清理

如果运行环境长期写入大量短期 key，需要额外考虑清理策略。

## 并发语义

`setnx()` 使用 `fopen($path, 'x')` 进行抢占创建。这能避免多个进程同时创建同一个文件，但它不是带 owner token 的完整分布式锁。

`setnxCache()` 使用 `lock:` 前缀 key 作为生成锁：

- 抢锁成功者生成并写入缓存。
- 等待者轮询读取缓存。
- 等待超时会抛出 `RedisException`。

虽然异常类名是 `RedisException`，当前 driver 仍然是文件实现。

## lock/unlock 限制

`lock()` 写入的是锁过期时间戳，`unlock()` 只按锁名删除。

这意味着：

- 解锁时不校验调用方是否持有该锁。
- 锁过期后其他进程可以删除并重新抢锁。
- 如果业务代码执行时间超过 `$occupy`，锁可能被其他进程重新获得。

## 修改扩展建议

- 改默认缓存目录：调整 `bin/autorun.php` 的 `Cache::init()` 参数。
- 改文件命名、序列化格式、过期清理：调整 `Driver`。
- 需要 Redis 语义时，优先使用或扩展 Redis 包，不要把本包直接改成 Redis driver。
